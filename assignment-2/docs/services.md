# Service documentation

Every service in the design, grouped by layer. "Key configuration" is what the Terraform in
[`../infra/`](../infra/) actually sets (file in brackets). The production region is **ap-south-1
(Mumbai)**, the closest AWS region to Bhutan; the Floci deployment runs the same code in us-east-1.

## Edge and frontend

| Service | Role | Why over an alternative | Key configuration | Connects to |
|---|---|---|---|---|
| **Amazon Route 53** | DNS for `exams.<university>` | Alias records to CloudFront are free and answer with CloudFront's current addresses. A university DNS server would need a CNAME and cannot alias the zone apex. Its 100% SLA beats an on-campus server that becomes a single point of failure on exam day. | Public hosted zone; `A` alias → CloudFront; ACM DNS-validation records (`edge.tf`) | CloudFront, ACM |
| **Amazon CloudFront** | Serves the app from edge caches; one HTTPS domain for app and API | Serving the app straight from S3 or an ALB would send every one of the 3,000 exam-start page loads to the origin. CloudFront caches them, terminates TLS near the user, and keeps `/api/*` on the same domain, so there is no CORS and no second certificate. | Default behaviour → S3 (CachingOptimized, OAC); `/api/*` → API Gateway (CachingDisabled, AllViewerExceptHostHeader so `Authorization` passes); HTTPS only; TLS 1.2_2021; PriceClass_200 (includes India edges); access logs to the logs bucket (`edge.tf`) | Route 53, WAF, ACM, S3 frontend, API Gateway |
| **AWS WAF** | Filters malicious traffic before it reaches the platform | A WAF at the edge stops attacks before they consume API Gateway or Lambda capacity, and AWS maintains the managed rule sets. Hand-written checks inside the API would run only after the request had already cost money. | Web ACL (scope CLOUDFRONT, us-east-1): AWSManagedRulesCommonRuleSet, KnownBadInputs, AmazonIpReputationList, and a per-IP rate limit of 50,000 per 5 min. The limit is generous because a whole exam hall can share one campus NAT address (`edge.tf`) | CloudFront, CloudWatch metrics |
| **AWS Certificate Manager** | TLS certificate for the custom domain | Free, auto-renewing public certificates. A purchased certificate must be renewed and uploaded by hand, and an expired certificate in exam week is an outage. | DNS-validated certificate in us-east-1, as CloudFront requires (`edge.tf`) | CloudFront, Route 53 |
| **Amazon S3 (frontend bucket)** | Hosts the single-page app (HTML/JS/CSS) | Static files need no servers. EC2 or containers running nginx would have to be patched, scaled and spread across AZs to do what S3 + CloudFront do with 11 nines of durability. | Private; Block Public Access on; readable only by this distribution through Origin Access Control; deny non-TLS; `config.js` generated by Terraform (`storage.tf`, `frontend.tf`) | CloudFront |

## Authentication, API and compute

| Service | Role | Why over an alternative | Key configuration | Connects to |
|---|---|---|---|---|
| **Amazon Cognito** | Role-based sign-in for 8,400 users | A managed user directory with token issuing, MFA and password policy. A hand-built login table would make the platform responsible for password storage. Cognito can later federate with the university's SAML/Entra ID directory without code changes. | User pool, email as username, no self sign-up; 12-character password policy; TOTP MFA (required for staff); advanced security ENFORCED; groups `students`, `tutors`, `admins` → `cognito:groups` claim; ID token 4 h, longer than any exam (`auth.tf`); the API function also verifies every token's RS256 signature, issuer, audience and expiry against the pool's JWKS (`app/functions/common/auth.py`), as a second layer behind the authorizer | Browser, API Gateway authorizer |
| **Amazon API Gateway (REST)** | The API front door: authentication, throttling, routing to Lambda | A REST API has a built-in Cognito authorizer, per-stage throttling, WAF compatibility and access logs, with no servers. An ALB + ECS service would need its own JWT check and scaling. An HTTP API is cheaper but has no WAF association and no usage plans. | Regional; `GET /api/health` (open); `ANY /api/{proxy+}` with the COGNITO_USER_POOLS authorizer; `OPTIONS` open for CORS; stage `prod` with throttle 1,000 req/s (burst 2,000), access logs, X-Ray (`api.tf`) | CloudFront, Cognito, Lambda (alias `live`), CloudWatch |
| **AWS Lambda – exam-api** | Business logic for both walkthroughs: start attempt, autosave, submit, presigned upload, tutor views, release | Scales per request in seconds, which suits a spike of 3,000 starts in 5 minutes. ECS Fargate would need tasks scheduled up before each exam and would pay for idle capacity the rest of the week. | Python 3.12, 1,024 MB, 15 s; in the private app subnets of **both AZs**; reconnects once if a failover drops its database connection; alias `live` with provisioned concurrency 100 for exam windows (removes cold starts); X-Ray active; own least-privilege role (`functions.tf`) | API Gateway, RDS Proxy, SQS marking, EventBridge, S3 (presigned URLs), Secrets Manager |
| **AWS Lambda – workers** (submission-processor, auto-marker, notifier) | Asynchronous work off the request path | Each scales with its queue's depth, can be capped, and costs nothing when idle. A cron job on EC2 would add latency and a server to look after. | SQS triggers, batch 10, `ReportBatchItemFailures` so only failed messages retry; max concurrency 20/20/5 (the notifier's 5 respects the SES send rate); the processor and marker run in the VPC, the notifier does not (it needs no database) (`functions.tf`) | SQS, RDS, S3, EventBridge, SES |

## Network

| Service | Role | Why over an alternative | Key configuration | Connects to |
|---|---|---|---|---|
| **Amazon VPC** (subnets, route tables, security groups) | Private network for everything that holds data | A database in a private subnet is unreachable from the internet. A public RDS endpoint protected only by a password is the rubric's "public database". | 10.20.0.0/16 across **two AZs**, three tiers per AZ, each a /19: public, private app (sized for Lambda network interfaces at peak), private data. Security groups chain Lambda → RDS Proxy → DB on 5432 only (`network.tf`) | All in-VPC services |
| **NAT Gateway** (×2) | Outbound internet for the private subnets | One per AZ, with each AZ's private route table pointing at its own NAT gateway, so the loss of one AZ never cuts off the other. A single NAT gateway would be a cross-AZ single point of failure. NAT instances must be patched and scaled by hand. | One per public subnet, Elastic IP each, per-AZ route tables (`network.tf`) | Internet Gateway, private subnets |
| **Internet Gateway** | Internet access for the public subnets (NAT) | Required by NAT gateways; managed and horizontally scaled with no capacity to plan. | Attached to the VPC; public route table 0.0.0.0/0 → IGW (`network.tf`) | NAT gateways |
| **VPC endpoints** | Private access to S3, SQS, Secrets Manager, EventBridge and KMS | Keeps service traffic on the AWS network and off the NAT gateways. That saves NAT data charges at exam-week volume, and these calls keep working even if both NATs fail. | S3 gateway endpoint on the private route tables; interface endpoints in both app subnets with private DNS (`network.tf`) | Lambda, S3, SQS, Secrets Manager, EventBridge, KMS |

## Data

| Service | Role | Why over an alternative | Key configuration | Connects to |
|---|---|---|---|---|
| **Amazon RDS for PostgreSQL, Multi-AZ** | Exams, questions, attempts, autosaved answers, assignments, submission records | The data is relational: an attempt's answers, deadline and submission are one transaction. Multi-AZ keeps a synchronous standby in the second AZ and fails over automatically (~1–2 min) with no committed write lost. DynamoDB would also scale but makes reporting and the submit transaction harder. Self-managed PostgreSQL on EC2 would leave replication and failover to us. | PostgreSQL 16, `db.r6g.large`, **multi_az = true**, data subnets in both AZs, gp3 100 GB autoscaling to 500 GB, KMS-encrypted, `rds.force_ssl=1`, 35-day backups + PITR (5-min RPO), deletion protection, Performance Insights, logs exported (`database.tf`) | RDS Proxy, Secrets Manager, KMS, AWS Backup, CloudWatch |
| **Amazon RDS Proxy** | Connection pooling between Lambda and RDS | Thousands of Lambda environments would each open a connection and exhaust PostgreSQL's `max_connections` during the exam burst. The proxy multiplexes them and holds client connections through a failover. Pooling inside the function cannot be shared across environments. | Subnets in both AZs, TLS required, auth from the Secrets Manager secret, pool max 90% / idle 50% (`database.tf`) | Lambda, RDS, Secrets Manager |
| **Amazon S3 (uploads bucket)** | Stores assignment files (PDF/ZIP, up to 50 MB) for 5 years | Cheaper and more durable than EBS or EFS. Presigned POST keeps 50 MB uploads off the API (API Gateway caps payloads at 10 MB, Lambda at 6 MB) and lets S3 enforce the size. Lifecycle rules move ageing records to cheaper tiers automatically. | Private, Block Public Access, versioned, **SSE-KMS** (bucket key), deny non-TLS. **Lifecycle:** Standard → Standard-IA 30 d → Glacier IR 180 d → Deep Archive 365 d → expire **1,830 d (5 years)**; noncurrent versions 90 d; abort incomplete multipart 1 d. CORS POST from the app origin only; `ObjectCreated` → SQS (`storage.tf`) | Browser (presigned POST/GET), SQS, Lambda, KMS, AWS Backup |
| **Amazon S3 (logs bucket)** | CloudFront and CloudTrail logs | A separate bucket keeps audit evidence apart from application data, with its own 5-year lifecycle. | Private, SSE-S3, Glacier IR at 90 d, expire 1,830 d (`storage.tf`, `monitoring.tf`) | CloudFront, CloudTrail |

## Asynchronous processing

| Service | Role | Why over an alternative | Key configuration | Connects to |
|---|---|---|---|---|
| **Amazon SQS** (uploads, marking, email queues + 3 DLQs) | Buffers work between producers and workers | A deadline-night burst of uploads or a 3,000-email release waits safely in a queue instead of overwhelming the database or SES. Direct S3 → Lambda invocation has no backlog to inspect and loses failed events after its retries. Dead-letter queues keep every failure for a person. | Standard queues, SSE-SQS, long polling 20 s, visibility timeout ≥ 6× the consumer timeout, maxReceiveCount 5 → DLQ (14-day retention); queue policies allow only this bucket / this event bus (`async.tf`) | S3, EventBridge, API, Lambda workers, CloudWatch |
| **Amazon EventBridge** | Platform event bus: `SubmissionReceived`, `ResultsReleased` | Producers publish facts without knowing who listens, so a later consumer (an LMS sync, plagiarism checks) is just a new rule. SNS fan-out has no content filtering on event fields and no archive or replay. | Custom bus `exam-events`; rules route SubmissionReceived → email queue and ResultsReleased → marking queue (fan-out); 30-day archive for replay (`async.tf`) | exam-api, submission-processor, SQS |
| **Amazon SES** | Sends tutor notifications, student receipts and result emails | Pay-per-message transactional email with bounce handling. Sending through the university's SMTP server from Lambda would hit its rate limits and spam filtering at 3,000 messages. | Verified sender identity; IAM limited to `ses:SendEmail` from that address; the notifier's concurrency cap keeps sends under the SES quota (`async.tf`, `functions.tf`) | Notifier Lambda |
| **Amazon SNS** | Delivers CloudWatch alarms to the operations team | The standard alarm target: one topic, any number of email/SMS/chat subscribers. | Topic `exam-ops-alerts`, encrypted with the AWS-managed key, optional email subscription (`async.tf`) | CloudWatch alarms |

## Security

| Service | Role | Why over an alternative | Key configuration | Connects to |
|---|---|---|---|---|
| **AWS KMS** | Encryption at rest | A customer-managed key gives a key policy, rotation and a CloudTrail record of every use. AWS-owned keys are invisible and cannot be audited. | One symmetric key with yearly rotation and a 30-day deletion window; used by RDS, S3 uploads, Secrets Manager and the backup vault (`security.tf`) | RDS, S3, Secrets Manager, AWS Backup, Lambda |
| **AWS Secrets Manager** | Database credentials | The password exists nowhere in code, Terraform variables or Lambda environment variables. Functions and RDS Proxy fetch it at runtime, and it can rotate. SSM Parameter Store SecureString has no built-in RDS rotation. | Generated 32-character password, KMS-encrypted, 30-day recovery window; read by the three VPC functions and the proxy only (`security.tf`) | Lambda, RDS Proxy, KMS |
| **AWS IAM** | Least privilege between every component | One role per function with only the actions and resources it uses. The API cannot read the uploads queue, and the notifier cannot reach the database. A shared broad role would let one compromised function do everything. | Per-function inline policies; `aws:SourceAccount` on every service trust; `ses:FromAddress` condition on the notifier (`functions.tf`, `database.tf`) | All services |

## Monitoring, audit and recovery

| Service | Role | Why over an alternative | Key configuration | Connects to |
|---|---|---|---|---|
| **Amazon CloudWatch** | Logs, metrics, alarms and the exam-day dashboard | Native metrics from every managed service with no agents. A self-hosted Prometheus/Grafana stack would itself need to survive an AZ loss. | Log groups (90-day retention); 8 alarms (API 5xx, p95 latency > 1 s, Lambda errors and throttles, RDS CPU, connections, free storage, email backlog age) plus one per DLQ → SNS; dashboard `exam-exam-day` (`monitoring.tf`) | Every service, SNS |
| **AWS X-Ray** | Traces a request through API Gateway and Lambda | Shows where autosave latency comes from (authorizer, function, database) during a load test. Plain logs cannot join the hops of one request. | Active tracing on the stage and all functions (`api.tf`, `functions.tf`) | API Gateway, Lambda |
| **AWS CloudTrail** | Audit trail of every API call, including who read which submission | Academic-integrity cases need evidence of access. CloudTrail data events on the uploads prefix record each GetObject/PutObject, and log-file validation makes the record tamper-evident. | Multi-region trail, log file validation, S3 data events on `uploads/submissions/`, logs kept 5 years (`monitoring.tf`) | S3 logs bucket |
| **AWS Backup** | Long-term, policy-driven backups of the exam records | A central plan with vault encryption and cold storage. RDS automated backups stop at 35 days, but the records must be kept 5 years. | Vault (KMS); daily backups kept 35 d; monthly backups moved to cold storage after 90 d and kept 1,830 d (`backup.tf`) | RDS, KMS |

## Delivery

| Service | Role | Why over an alternative | Key configuration | Connects to |
|---|---|---|---|---|
| **Terraform** | Infrastructure as code for every resource above, and the frontend | One declarative configuration rebuilds the platform from nothing; `plan` shows changes before they happen. Console-built infrastructure cannot be reproduced or reviewed. CloudFormation is AWS-only and slower to iterate; Terraform runs unchanged against Floci and AWS. | AWS provider pinned to 6.57.1; `floci.tfvars` vs production defaults; the frontend and its `config.js` deployed by the same apply (`infra/`) | All services |
| **GitHub Actions** | CI/CD: every push to `main` builds, deploys and smoke-tests | Lives next to the code, needs no build servers, and has free minutes for a course repository. CodePipeline + CodeBuild would need source mirroring and more setup. On AWS it deploys through an OIDC-federated role, so no long-lived keys sit in GitHub. | Workflow `.github/workflows/assignment-2.yml`: build the functions, start Floci 1.5.34 in the runner, `terraform apply`, run both walkthroughs as smoke tests, upload evidence; path-filtered to `assignment-2/**` | GitHub, Terraform, Floci/AWS |
